# Domain-specific implementation rules

Read relevant sections before changing domain behavior. [AGENTS.md](../../AGENTS.md) contains mandatory authorization, validation, audit, and verification requirements. Public guides explain supported user-facing setup; this file records implementation constraints.

## Membership and identity

- Resolve active workspace membership for every operation. Admin/Agent privileges do not imply source grants or approval authority. Recheck current eligibility for approvals, including group/manager targets and required rejection comments; never decide on a user's behalf.
- Manual users are invited through hashed, expiring recipient-bound tokens and current inviter authorization. Preserve intended workspace/role on acceptance; encrypted queued email payloads require configured delivery. Enabled identity providers hide/reject manual invitations as implemented.
- Protect self/owner deletion and self-deactivation on the server. User removal affects workspace membership, not the global account or audits. Enforce current versions and confirmation.
- Workforce fields reference shared tables; manager references an active user. Import only allowlisted bounded SCIM/OIDC attributes, resolve references in the same provider/workspace, and never infer app roles/source grants from profile values. Identity-managed fields remain read-only locally.
- OIDC binds issuer/subject with validated tokens, state/nonce/PKCE as implemented, fixed callbacks, safe endpoints, and browser-bound one-time state. Do not claim unimplemented token refresh, group sync, or authentication methods. OAuth login does not grant knowledge access.
- Verified custom portal domains require DNS TXT ownership, configured routing, HTTPS/secure cookies, and verified workspace-host/origin binding. DNS errors fail closed; do not claim automatic DNS/TLS provisioning or custom OAuth callbacks.

## Requests, approvals, tasks, and journals

- Keep support chats independent of requests. Create requests only on explicit conversational form submission (incoming support email is an explicit submission). Keep legacy chat-only records out of lists without deleting history. Submission and assistant receipts are idempotent.
- One request retains one originating chat; one chat may contain several requests. Catalog selection offers the exact permitted published form without requiring AI. Validate offer response ID, current revision, field types/options, answers, and references on submission.
- Request access never grants another person's private transcript/files. Operator conversations belong to their initiating operator; their workbench replies are public comments, not another user's private AI messages. Do not send internal journals to a provider.
- Request self-assignment is audited/versioned, limited to current authorized operators, and refuses takeover. Group/task references must exist. Tasks use current group/direct-assignment rules, and a resolved parent blocks changes until reopened. Preserve parent-chat/note isolation for task-only access.
- Work-note authorization is independent of request ownership: an Agent requesting outside their groups cannot read staff notes simply because they own the request. Read Only never posts. Filter notes/events server-side, not only in JSX.
- Mentions validate active membership, exact selected IDs, record read access, and note access where applicable. Persist entry plus notifications atomically; use metadata-only emails, fresh delivery/read checks, single claims, no uncertain resends, no self-notification, and personal Inbox archive/view state. Never grant permission through a mention.
- Inbox includes current assignments, eligible approvals, and authorized mentions. Requester ownership alone does not create assigned work. Archive is actor/workspace scoped, never a status/access change. Requests/Inbox/Audit use native database access/search/order/count/page queries, including legacy submission checks and revoked approvals.
- Admin bulk deletion is bounded to 100 requests/authored articles with explicit selection/effects confirmation. Preserve audit/run history, handle unshared attachments, stop pending runs, and reject deletion during active/uncertain delivery. Recheck request existence before every workflow effect.

## Workflow and agent services

- Typed tools are the only executable proposal/action interface. Provider adapters preserve native calls/results/signatures; no prose/JSON/code-fence extraction. Keep Admin configuration tools distinct from support tools, with bounded rounds and reauthorization.
- Explicit Admin group requests use the shared group service and verified results; resolve all requested groups then continue the workflow/form in the same turn. Infer trigger aliases; never ask admins for matching phrases. Refresh current group context after writes.
- Groups unify assignment/approval purposes, both default enabled on creation. Preserve stable legacy queue names/approval IDs. Only active assignment-enabled groups route work; active approval-enabled groups require eligible members. Stored routing instructions are data, not code.
- Publish validated immutable TypeScript/source/config revisions. Draft autosave follows edits/chat only; retain separate published settings and explicit Publish/Unpublish. History is actor/workspace scoped and never autosaves an old definition over the current draft.
- Type-check/run in bounded QuickJS/WASM threads. Gateway authorization independently verifies current role, published audience/department references, declared action IDs/destinations, existing groups, approval authority, and connector policies. No arbitrary imports, files/network, credentials, clock/randomness, eval/vm, or expression evaluation.
- Persist frozen run inputs, leases, idempotency receipts and recoverable step state. Approval pauses are durable. Never claim exactly-once execution or resend uncertain external effects. Tests simulate effects; a visual declaration does not prove an executed branch.
- Reference fields use validated table IDs and current authorized lookup labels/IDs; revalidate on submission and retain display-label snapshots. Reference access does not expose full records. Department scope references a real workspace Departments record, not a hard-coded list.
- Settings must affect actual server behavior: catalog visibility/category/image, audience, default group, receipt, bounded timeout/concurrency. Keep visual cards high level and code in highlighted Code views; metadata edits preserve executable code, routing edits explicitly regenerate it.
- Request chat actions are scoped reviewable proposals with current record/version checks and one-time claims; never silently mutate, approve, delete, or grant tools based on prompt instructions. Both agents get only the current person's bounded authorized profile context.

## Knowledge, tables, and demo data

- Articles have one owning base and at least one valid topic on save/publication; existing unclassified articles stay readable until edited. Use Tiptap and sanitized HTML. Base/topic/article permissions intersect; only permitted Published articles reach employees or retrieval.
- AI article edits require a sanitized immutable preview, explicit approval, stale-version protection, one-time claims, and audit. Never autosave a proposal; approved saves bind the conversation/history to the saved article. Editorial status does not grant access.
- Knowledge attachments inherit article access, download as attachments, and are not automatically extracted or sent to providers. Chat uploads bind actor/workspace/conversation; queue IDs only, reauthorize before use/publication, and reject unsupported formats truthfully.
- Imported source titles/snippets/content require fresh delegated source or explicitly accepted managed-snapshot policy. Source failure denies access; do not silently switch policy. Preserve stable source IDs, destination ownership, completed generations, and last successful snapshots.
- Retained ServiceNow imports use the installed authenticated permission bridge, GlideRecordSecure, field ACLs, and KBKnowledge.canRead as the delegated identity. Historical import compatibility is not new Connector support. Do not restore retired adapters, external connected-agent registration/tokens/MCP, or a Knowledge Sources shortcut.
- Local semantic retrieval uses Ollama nomic-embed-text and separate Qdrant collections for authored/source content. Candidates require current publication/generation/grants/access checks in the authoritative selected database. Mark fresh generations pending atomically, renew worker leases, publish readiness only for current generations, and retire vectors/chunks with durable tombstones. Outages may use truthful authorized keyword fallback; never embed through chat providers or widen access.
- Data Tables is Admin-managed configuration. Shared typed reference tables/custom values do not grant permissions or enter model context automatically. Preserve built-in field IDs/types/references and identity-provisioned values; custom schema removals require explicit confirmation. Source-managed built-ins stay edited through their proper service/view.
- Custom table deletion requires the exact typed name, removes associated records, preserves audits, and cannot delete built-ins. Schema edits require explicit reviewed Save and versions; keep authoring conversations separate from workflow/support chats.
- Demo data is loaded/removed only in Settings via versioned fictional industry configuration, tagged in the current workspace. Serialize/idempotently recover changes; workflow submissions inherit tags. Exclude demo options from real-record lookups and enforce persisted-tag checks on writes. Preserve real data, identities, audit/published history and access policies; disclose any required legacy reference cleanup. Block cleanup during active/uncertain delivery and retire vectors.
- Demo workflow conversations include an example prompt and preserve actor-specific selected history/New Chat state. Demo approvals use real permission checks; any approval permission change requires consent and conditional restoration without overwriting later edits.

## Connectors, jobs, and governance

- The connector registry defines implemented fields/auth methods/actions. Use dedicated configuration pages, alphabetic lists, consistent Not Configured states, encrypted database-only app/SMTP credentials, and version checks. Saving credentials invalidates prior OAuth/install generations; do not require environment updates or restore credential fallbacks.
- Allowed Actions defaults on only for implemented capabilities; enforce policy at receipt, generation, and delivery. Receiving support messages does not crawl channel history or grant shared knowledge access. Unknown adapters fail closed; do not advertise unimplemented workflow effects.
- Slack verifies raw-body HMAC/fresh timestamps and exact installed team/app; deduplicate durably and recheck explicit active identity bindings and current install generation. Reply privately in channels; never infer identity or grants from names/email text.
- Teams verifies Microsoft signature, issuer, audience, lifetime, channel endorsement, matching service URL, configured tenant and explicit active-user mapping. Private bot replies, ID-only durable jobs, and fresh pre-generation/delivery checks are mandatory. Gmail/other email senders remain isolated; OAuth possession is not end-user authorization.
- Durable jobs use authoritative database states/leases, ID-only payloads, bounded concurrency/pages/bytes, retry delays/backoff/jitter, and Redis AOF/no eviction. Reconcile after outages; uncertain provider delivery requires review, never automatic duplicate sends.
- Governance captures API and database writes, workflow/approval/version changes, and all nested tools with root/parent/trigger/resource/response/tool-call correlation. No raw arguments, credentials, prompts, form values, private files or journals in audits. Audits are workspace-scoped Admin/Read Only views, not cryptographically immutable logs.
- Audit retention defaults off. Confirmed Admin cleanup uses current policy, scoped leases/batches, counts and failure records, and preserves running operations. Search/filter/count/export stays server-side, including workflow/trigger filters. Exports cap 10,000 and neutralize CSV formulas; do not claim transactional snapshots.
- Reports use real recorded activity, not fabricated views/citations/resolutions. My Work is personal assignments; My Team is workspace-wide for Admin/Read Only and own groups for Agents. Report counts/exports cannot broaden record access.

## Database-boundary review

Use shared `queryValues.js` helpers where validated scalar values enter database filters, including recipient IDs, table IDs, workspace scope, versions, and worker-loaded values. Keep keys/operators fixed and parameters typed. A validation check in a caller may be missed by a new call path or a static analyzer; make the database contract visible in the query itself. Test object/array/operator input, cross-workspace data, stale versions, and revocation on MongoDB and PostgreSQL. Review current CodeQL runs on the final commit; local tests cannot mark GitHub alerts resolved. Keep the database test workflow required in repository branch rules and enable CodeQL for pull requests; repository rule configuration is an administrator action, not a claim that editing this file enforces it.
